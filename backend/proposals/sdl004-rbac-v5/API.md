# V5 API contracts

Use the signed-in user's Supabase session for public RPCs. The server derives the actor. The private schema, verified cases and platform grant maintenance have no browser contract. The Worker advertises `rbacVersion: 5` in the existing capabilities response when the database and gate allow it. Each RPC has named arguments in its migration. Calls that write access events, including reads of sensitive data, use HTTP POST.

| Area | Operation and client behavior |
|---|---|
| Delegation | `sdl_v5_set_staff(p_scope,p_target,p_role,p_grant,p_reason)`. Scope is an organization for `club_admin` and a team for `manager` or `coach`. A revoked assignment needs explicit recovery review. |
| Registration and roster | `sdl_v5_register_player(p_team,p_name,p_jersey,p_request,p_reason)` returns a player UUID. Retain the request UUID across retries. `sdl_v5_set_roster` adds or ends an assignment. |
| Transfers | Request with player, source team, destination team and reason. `sdl_v5_request_transfer` returns the request UUID. `sdl_v5_approve_transfer` consumes that UUID, acting capacity, destination jersey and reason. False means approvals remain outstanding. The destination administrator completes cross-club registration after the guardian agrees. |
| Settings and profiles | `sdl_v5_team_settings` supports a scoped name change or archive. `sdl_v5_edit_profile` takes the player, allowlisted field patch, exact expected previous values, reason and optional verified support case. Send baseball and legal changes separately. Photo eligibility is advisory until private avatar storage is accepted. |
| Invitations and contacts | Existing invitation issue, revoke, list and redeem signatures remain. Issued manager invitations bind to a team. Reissue older outstanding invitations. `sdl_v5_restrict_guardian` accepts a user, organization, optional team and reason. `sdl_v5_unlink_guardian` requires a separately verified case. `sdl_v5_family_contacts` selects family or registration fields by purpose. `sdl_v5_set_own_contact` writes the verified guardian's own phone. |
| Performance | Keep the pilot submission, review, growth and correction contracts. For an official correction use `sdl_v5_correct_official(p_prior,p_protocol,p_value,p_date,p_evidence,p_request,p_reason,p_video)`. Preserve request keys across retries. Show units from the protocol. For legacy official corrections, explain the revision in the required evidence note. Coaches review pending parent submissions independently. |
| Private history and export | `sdl_v5_private_statistics` and `sdl_v5_export_private_history` take player, optional last session UUID and limit (1–200). `sdl_v5_export_statistics` takes scope, resource UUID, optional last official-statistic UUID and limit (1–200). Use a null resource only for platform export. Use PostgREST CSV content negotiation for spreadsheet import. Exports contain measurement columns and identifiers. |
| Media | Use authenticated GET on `/v2/submissions/{id}/playback` or `/download`. Both support byte ranges. Download returns an attachment and records authorization before storage access. An authorization event does not establish byte delivery or completion. `sdl_v5_confirm_subject` records independent single-athlete confirmation. Unknown subjects cannot be downloaded. Multiple-subject assets require separately verified permissions. |
| Compatibility | Object-aware v1 playback and list calls can use the v5 decision when the submission gate is open. Legacy-only assets require provenance reconciliation. Uploads use an explicit supported category and UUID idempotency key. Older clients lacking those parameters must use the v2 upload flow. |
| Clubhouse | `sdl_v5_clubhouse_sessions(p_team,p_after,p_limit)` pages by last result UUID with a maximum of 100. Existing leaderboard and roster calls remain. Request a fresh, explicit standing receipt through `sdl_004_set_statistic_consent` with the accepted notice and all four current baseball metrics. Keep video choices separate. Ship notice changes only after privacy review. |
| Audit | `sdl_v5_audit_history(p_scope,p_id,p_before,p_limit)` returns descending event IDs with a maximum of 100. Supported scopes are platform, club, team, own and downloads. Downloads takes a child player ID. New event scope is captured at occurrence. |

Handle authorization denial by clearing the affected view. A stale revision, reused request key, or changed enrollment can return conflict. Refresh the selected resource before retrying. Invalidate cached player data and media state on account, role or player changes. No frontend should consume a database secret, inferred role hierarchy or service-only upload finalization RPC.

## MEDIA-03A clean-start media contract

Media requests require an active v5.1 authorization contract with `rbacVersion: 5` and `mediaRevision: "v5.1-clean-start"`. Existing clients continue to send the user's bearer token. Worker gates control routing. Direct database permissions remain independently governed.

| Request | Gate | Authorization and response |
|---|---|---|
| GET /v2/submissions?player_id=UUID | MEDIA_PLAYBACK_ENABLED | `sdl_004_list_submissions`; authorized empty collection returns `200 {"items":[]}`; unauthorized collection returns 403. |
| GET /v2/clubhouse?team_id=UUID | MEDIA_PLAYBACK_ENABLED | `sdl_004_clubhouse_videos`; active team eligibility and object sharing checked. |
| GET /v2/submissions/UUID/playback | MEDIA_PLAYBACK_ENABLED | `sdl_v5_authorize_playback` then exact private R2 metadata and object. Full 200 or single-range 206; private/no-store. Chromium derives previews from authorized video bytes in memory. |
| GET /v2/submissions/upload-eligibility?player_id=UUID | MEDIA_UPLOAD_ENABLED | `sdl_004_submission_can_submit`; an advisory boolean. The POST rechecks permission. |
| POST /v2/submissions?player_id=UUID&category=pitching\|batting\|throwing | MEDIA_UPLOAD_ENABLED | Permission, bounded MP4 body, UUID idempotency key, and payload hash; caller reservation `sdl_004_reserve_submission`; private R2 put; service-only `sdl_004_finish_submission`. Returns 201 with ID, player ID, category and status. Reuse the request key on uncertain outcomes. |
| GET /v2/review?team_id=UUID | MEDIA_REVIEW_ENABLED | `sdl_004_review_queue`; scope and playback eligibility checked. |
| POST /v2/submissions/UUID/review | MEDIA_REVIEW_ENABLED | `sdl_004_review_submission`; independent current reviewer required. |
| POST /v2/submissions/UUID/publish | MEDIA_PUBLICATION_ENABLED | `sdl_004_publish_submission`; requires a recorded independent single-subject confirmation before publishing. The separate `sdl_v5_confirm_subject` RPC remains subject to the existing direct-API hold. Empty teams unpublish and retain subject evidence. |
| GET /v2/submissions/UUID/download | MEDIA_DOWNLOAD_ENABLED | `sdl_v5_authorize_download`; existing scoped attachment policy only. Platform-derived attachment authorization requires AAL2. |
| /v1/authorize, /v1/media and its object paths | Retired | 410. No database, Auth or bucket lookup. |

All six media flags are off in the package. The added MEDIA_ARCHIVE_ENABLED flag controls private library removal. `SUBMISSIONS_ENABLED` still guards the remaining v2 pilot, capability, enrollment and non-media functions. Dedicated media routes are independent of that flag. The general frontend submission workspace retains its separate `SUBMISSION_FEATURES_ENABLED` hold. Worker media flags cannot open a held RPC.

401 denotes expired, invalid or revoked authentication. A 403 is explicit authorization denial. A 503 with `code: "media_disabled"` means the feature gate is closed. Other 503 responses indicate an unavailable dependency, invalid server response or incompatible backend contract. A 404 after authorized playback means metadata or bytes were unavailable. A 416 means the range is unsupported. No browser response includes R2 object keys or privileged credentials.

### Option C amendment for MEDIA-03B

Authorize attachment downloads for verified current team members only when a clean-start video is approved and explicitly published to their independently eligible team, current sharing consent covers that use, the current enrollment and recording/storage authorization are valid, and independently verified single-subject and retention requirements are met. Evaluate the intended download use separately from playback. Keep pending, rejected and merely private clips outside this team grant. Scope requests to the same organization, team and object, recheck each request including ranges, and record authorization with actor, object and the eligible team scope. Ordinary independently scoped rights and the AAL2 requirement for platform-derived downloads remain in place. Prepare positive and negative coverage for membership changes, consent withdrawal, unknown subjects and other teams before authorizing activation in MEDIA-03B. MEDIA-03A has no team attachment grant.

## MEDIA-03A-R1 staging library removal

`POST /v2/submissions/UUID/archive` requires `MEDIA_ARCHIVE_ENABLED` and caller-JWT `sdl_v5_archive_media`. `sdl_v5_media_archive_ids` provides advisory object permissions to the private list when the archive gate is enabled. Both RPCs default to no execution grant. Only currently scoped Club Admin or Coach, or a verified participating guardian who submitted their own still-pending clip, may archive an unpublished clean-start record. Independent roles remain independent. Team Manager and Platform Admin alone receive no archive grant. Archive records actor/time and clears publication metadata; the stored object and audit evidence remain private and intact. No physical deletion. Archived clips are excluded from playback and publication. This is a proposed staging policy, not an approved permanent deletion policy. No hosted migration or activation is performed by this commit.
