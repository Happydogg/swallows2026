Each playback reauthorizes even if a thumbnail was fetched earlier. Approved frontend navigation, analyzer settings and read-only roster discovery still supply the selected scope. The separate submission workspace retains its own front-end and server holds. Legacy `drill_videos` helpers remain safety-locked and the login data projection supplies no legacy clips.
- The clean-start SQL distinguishes new reservations from old rows. Only a matching finalized new reservation can produce a playable clean-start record. Old records and objects are retained. Publication consumes existing independent confirmation, while unpublish preserves it. Object playback uses current recording, enrollment, role and subject checks. Sharing consent withdrawal still removes team access. The patch does not rebuild historical consent or rewrite legacy material.
- Uploads enforce a declared 1–20 MiB size, exact received length, MP4 content type and an ISO BMFF signature. This signature check is not a full media decoder or content inspection. A deterministic payload hash and caller-bound reservation protect retries. R2 receives a server-owned key. Failed or uncertain finalization leaves the object private for separately approved recovery. Browser and service credentials are separated. No object deletion is in the runtime workflow.
- For containment, close all five media gates first and retain the existing wider submission hold. This stops Worker dispatch without changing object or audit state. Preview, playback and upload UI can be withdrawn independently. Verify direct PostgREST grants and Storage paths separately. Use the clone rehearsal to close affected public RPC EXECUTE privileges and verify effective ACLs, including inherited grants. Keep all state and audit rows.
